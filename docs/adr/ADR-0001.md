# ADR-0001：错误管道保持异常范式（不转 Result）

- 状态：Accepted
- 日期：2026-07-12
- 范围：`@115master/drive115`（及消费方 `@apps/monkey`）

## 上下文

架构深化评审（候选 2 · 贯通错误管道）中，需决定错误从 `BaseApiClient.handle()` 流出的形式：

- **A. 异常范式**：handle 照常抛，throw 对象自带结构化 `action`；`onError` 收 `ErrorResult` 投影。
- **B. Result 范式**：handle 不抛，返回 `{ ok, data, error }`，消灭 try/catch。

## 决策

选 **A**。错误管道保持异常范式。

## 理由

- 触发本轮深化的真实缺陷（`InfraError.retryable` 丢失，导致网络错误永不提示重试）在异常范式内即可修复——让 handle 边界归一化错误、产出 `action` 即可，无需改控制流。
- Result 范式是独立的、更大的变革：所有 client 方法签名与 20+ 调用方需重写，与「贯通错误管道」这一聚焦目标耦合会放大风险与评审负担。
- 调用方多数靠 `res.state` 判成败、本就不 catch；异常范式的改动面集中在 drive115 内部 + 少数 catch 点，向后兼容更好。

若未来错误处理复杂度（如批量请求、可恢复与不可恢复错误的组合）让异常控制流变得笨重，可重新评估 Result 范式——届时应由具体场景驱动，而非泛化迁移。

## 结果

- `handle()` 抛 `Drive115Error`（唯一对外失败类型，自带 `action` getter）。
- `onError` 回调收 `ErrorResult`（`Drive115Error` 的纯数据投影）。
- `InfraError`（网络层）在 handle 边界经 `fromInfra` 转换为 `Drive115Error(NetworkError)`。

### decideAction 规则

| code | action |
| --- | --- |
| SessionExpired | relogin |
| CaptchaRequired | verify |
| DecodeError / NotFoundM3u8File / NetworkError | retry |
| 其他 | `retryable ? retry : none` |
