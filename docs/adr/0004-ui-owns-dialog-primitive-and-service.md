# UI 包同时拥有 Dialog 原语与命令式服务

`@115master/ui` 同时提供应用无关、由状态驱动的 Dialog 原语，以及基于配置对象的命令式 alert、confirm、prompt 与自定义实例服务；应用代码优先调用命令式服务。服务通过工厂为每个应用、Story 或测试创建独立实例，由 Dialog Host 渲染，并通过注入供组件消费；不保留模块级全局容器，非组件代码直接持有应用创建的实例。UI 包不内置任何语言的用户可见文案，默认操作与提示文案由应用在创建服务时注入并允许单次覆盖。标题、内容与按钮文案统一接受字符串、VNodeChild 或 render function；复杂组件由调用方通过 `h()` 组合，渲染错误交给配置的 `onError`。命令式服务统一管理异步确认：支持 `false` 阻止关闭、Promise pending、确认按钮 loading、防重复提交与调用方 `onError`，不擅自显示错误反馈；pending 期间禁用所有用户关闭路径，只保留程序化关闭用于超时、取消请求或卸载收尾。Prompt 保留 defaultValue、placeholder、inputType、multiline、rows、required 与 maxLength，输入标签由单次配置或工厂文案集提供，必填失败显示可访问错误；单行 Enter 提交，多行 Enter 换行且 Ctrl/Cmd+Enter 提交，复杂校验与多字段表单使用自定义 Dialog。Escape 与蒙层关闭默认启用并允许单次覆盖：alert resolve `void`，confirm 返回 `false`，prompt 返回 `null`，自定义 handle 分别返回 escape 或 backdrop；pending 期间两条路径都失效。服务支持受控 Dialog Stack，只有栈顶可交互，嵌套反馈关闭后恢复下层焦点，`closeAll()` 按后进先出清理。取消属于正常 Dialog Outcome：`alert` 关闭后 resolve，`confirm` 返回布尔值，`prompt` 返回字符串或 `null`，`create` 立即打开并返回一次性 handle；handle 只提供 `close()`、`destroy()` 与只结算一次的 `closed` Promise，需要再次显示时重新创建。自定义 handle 的 `closed` 以结构化 Dialog Close Reason 区分 confirm、cancel、escape、backdrop、programmatic、destroy 与 close-all；只有配置或内部故障 reject。Dialog 保留 md、lg、xl、full 尺寸，移动端从底部呈现、sm 以上居中，外壳使用 panel Glass，内容自行管理内部布局与滚动。Monkey 的 App Dialog Adapter 扩展 `history?: boolean`，通过 router 与 handle 生命周期实现浏览器后退关闭；UI 配置不包含 history。相比只迁移原语，这扩大了 UI 公共契约，但让通用 Dialog 编排可以跨应用复用，同时仍阻止 UI 包依赖 Monkey router、挂载节点与业务流程。
