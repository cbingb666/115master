# 测试指南

## 测试策略

- 遵循测试金字塔，按改动风险执行适用的静态检查、单元测试、组件测试和构建验证。
- UI 或交互改动默认先进行用户验收测试（UAT），Playwright 用于后续端到端测试（E2E）或冒烟测试。

## 验收流程

1. 提供可访问的预览、操作步骤和预期结果，请用户验收。
2. UAT 通过：跳过 Playwright，并记录“用户人工验收通过，未运行 Playwright”。
3. UAT 失败、无法执行或结果不确定：使用 Playwright 复现、诊断并回归验证。

用户已主动给出明确结论时，无需重复请求验收。

## E2E 例外

用户明确要求 Playwright/E2E，或自动化测试本身属于交付内容时，直接执行，不受 UAT 前置流程限制。

## 结果报告

分别报告代码验证、UAT 和 E2E 结果。仅在实际运行 Playwright 并通过后，才能声明“Playwright 验证通过”；构建成功或页面可访问不等同于浏览器交互验证通过。
